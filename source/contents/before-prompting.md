# 프롬프트보다 먼저 설계해야 할 것

프롬프트를 길게 쓰는 것보다 중요한 일은 모델이 해결해야 할 작업을 명확하게 만드는 것입니다. 입력과 출력, 성공 기준이 흐릿하면 표현을 바꿔도 결과가 안정되기 어렵습니다.

## 작업을 정의하는 네 가지 질문

- 누가 이 결과를 사용할 것인가?
- 어떤 정보가 반드시 포함되어야 하는가?
- 어떤 형식으로 전달되어야 하는가?
- 무엇을 실패로 판단할 것인가?

## 맥락은 구체적으로

“잘 써줘” 대신 독자, 목적, 길이, 어조를 알려줍니다. 예시를 제공할 때는 결과만 보여주지 않고 어떤 특징을 따라야 하는지도 함께 설명합니다.

## 평가 가능한 출력

좋은 프롬프트는 결과를 검토하기 쉽습니다. 항목 수, 근거 표시 방식, 금지할 내용처럼 확인 가능한 조건을 사용하면 사람의 검토와 자동 평가 모두 단순해집니다.
